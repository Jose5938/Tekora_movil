# M3.2 · Aplicación del solicitante

M3.2 continúa la PR móvil #8 desde `81f322278fe6e2f993dc64afc6a7a6094b919792`. Usa los contratos de Laravel `/api/v1` y conserva el diseño, las rutas privadas y el almacenamiento de sesión de la app.

## Funciones y contratos

| Pantalla | Comportamiento | API reutilizada |
| --- | --- | --- |
| Inicio, Expertos y catálogo | Buscar prestadores, abrir su perfil y recorrer sus servicios y reseñas paginados. Filtrar servicios por las categorías activas. | `GET /providers`, `/providers/{id}`, `/providers/{id}/services`, `/providers/{id}/reviews`, `/categories`, `/services`, `/services/{id}`, `/services/{id}/reviews` |
| Registro y recuperación | Solicitar el correo, pegar el código completo y confirmar el registro o guardar una contraseña nueva. La sesión se inicia por separado. | `POST /auth/register`, `/auth/register/confirm`, `/auth/forgot-password`, `/auth/reset-password`, `/auth/login` |
| Mi cuenta | Consultar los datos de la propia cuenta, guardar el nombre y elegir una foto JPEG, PNG o WebP de hasta 2 MiB. La imagen privada se descarga con Bearer y vive en memoria mientras se usa. | `GET/PATCH /me/profile`, `GET/POST /me/photo`, `POST /auth/logout` |
| Actividad | Acceso directo a solicitudes, reservas, historial de servicios completados, conversaciones y avisos. | `GET /inquiries`, `/inquiries/{id}/messages`, `/reservations`, `/reservations?status=completed`, `/notifications` |
| Reseñas | Leer las propias, publicarlas tras una reserva completada y retirarlas conservando el historial privado. Seguimiento enlaza la acción indicada por Laravel. | `GET /reviews`, `/reviews/{id}`, `POST /reservations/{id}/review`, `PATCH /reviews/{id}/withdraw` |
| Contratación | Continúa el recorrido de M3.1 con cotización, propuesta, reserva y confirmación B2. El comprobante y el estado de prueba se consultan en la cotización asociada. | `/inquiries/{id}/journey`, `/inquiries/{id}/quotes`, `/quotes/{id}/accept`, `/inquiries/{id}/reservations`, `/reservations/{id}/checkout-context`, `/reservations/{id}/demo-checkout` |

Se corrigió el envío de `q` vacío, que Laravel rechaza. El acceso Expertos abre una búsqueda dedicada y cada ficha lleva a los detalles de los servicios de ese prestador. Las vistas de catálogo y de prestador muestran estados vacíos y reseñas públicas sin identidad del autor.

Las fotos y cambios de nombre requieren sesión y se comprueba que la respuesta pertenezca a la cuenta activa. Android conserva el almacenamiento seguro existente. En Expo Web, una recarga vuelve a pedir el inicio de sesión. Las páginas de ayuda indican el alcance de favoritos, direcciones, preferencias, términos y métodos de pago. Esas opciones carecen de persistencia o de una fuente oficial en los contratos actuales.

## Publicar trabajo

La pantalla indica que la publicación aún no está disponible y lleva al cliente al catálogo o a sus solicitudes. El backend todavía necesita un recurso de trabajos del cliente con creación, listado propio, edición, cancelación y reglas de transición. También hacen falta el listado de oportunidades para prestadores autorizados, la presentación y selección de propuestas, la apertura de una conversación asociada y pruebas de autorización, concurrencia y privacidad. Las fotos opcionales necesitan un almacenamiento separado con control de acceso. Este flujo queda para una fase independiente.

## Windows y Android

Usa un clon nuevo de Expo y un backend con datos sintéticos. Para revisar tarjeta ficticia, efectivo, reserva y comprobante desde Windows, usa un clon independiente de Laravel con la rama de la PR #58 y sigue las instrucciones de su laboratorio B3.2. El lanzador crea una SQLite temporal marcada y escucha en loopback. Para probar también W7.1 con el prestador web, usa una copia local revisada que contenga ambas PR, #51 y #58. Ninguna de las dos se considera incluida en `main` en esta validación. [Laravel #51](https://github.com/Fernando261/tekora-project/pull/51) · [Laravel #58](https://github.com/Fernando261/tekora-project/pull/58)

```powershell
git clone --branch codex/m31-tekora-mobile-checkout-ui https://github.com/Jose5938/Tekora_movil.git Tekora-Movil-M32-Pruebas
Set-Location Tekora-Movil-M32-Pruebas
npm ci
$env:EXPO_PUBLIC_API_BASE_URL = 'http://127.0.0.1:8097/api/v1'
$env:EXPO_PUBLIC_ALLOW_LOCAL_HTTP = '1'
npx expo start --localhost --web
```

Ajusta el puerto solo si el lanzador informa otro. Con Expo iniciado, usa otra terminal del clon para ejecutar `npx tsc --noEmit`, `npm test` y `npx expo lint`. Para un export web verifica con `npx expo export --platform web`. El HTTP local se admite en modo de desarrollo. Para ejecutar el export fuera de Metro, configura una API HTTPS de pruebas.

1. En Expo Web, inicia sesión con el cliente sintético del lanzador. Busca **Estudio Nodo** y abre uno de sus servicios. Usa otro servicio sintético publicado si quieres crear una solicitud que ese cliente todavía no tenga.
2. En **Mi cuenta**, guarda un nombre y elige una imagen sintética. Sal y vuelve a entrar para verificar ambos cambios. Revisa solicitudes, reservas, historial, reseñas y notificaciones.
3. Abre la reserva retenida del laboratorio. Elige tarjeta de prueba aprobada o efectivo y regresa a la reserva para confirmar dentro de los 900 segundos. Consulta el comprobante desde **Seguimiento → Cotizaciones**. Verifica tarjeta rechazada, efectivo pendiente y vencimiento con reservas nuevas del laboratorio.
4. Completa el servicio desde la cuenta sintética del prestador una vez vencido su horario. Abre **Seguimiento → Escribir reseña**, publícala y revisa la aparición en el perfil público. Retírala desde **Mis reseñas** y comprueba que desaparece del catálogo.
5. Para validar registro y recuperación de principio a fin, conecta un SMTP de pruebas que capture los correos sintéticos. Prueba pegar el código completo, usar un código inválido y comprobar que una sesión anterior deja de ser válida después de cambiar la contraseña.

En Android, usa un emulador o teléfono con una compilación de desarrollo y un backend HTTPS autorizado con cuentas sintéticas. Configura `EXPO_PUBLIC_API_BASE_URL` en la terminal y ejecuta `npx expo run:android` desde el clon móvil para validar el selector de fotos en el dispositivo. Para el checkout B3.2, usa Expo Web en la misma máquina que Laravel. El loopback del emulador o de un teléfono es propio del dispositivo. La protección del checkout se conserva y entrar por LAN o mediante un túnel general queda fuera del laboratorio.
