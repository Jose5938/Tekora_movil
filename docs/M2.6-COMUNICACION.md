# M2.6 · Conversaciones y notificaciones

Incremento apilado sobre M2.5. Contrato OpenAPI 1.4.0 del backend `a21802f0917132919b0be34087fee03236de2dc0`.

La vista de chat usa conversaciones propias y, desde cada solicitud, muestra mensajes según cursor opaco. El servidor controla `can_send`. Los mensajes salen con cuerpo normalizado y un UUID estable para la intención. La app conserva el UUID y una huella SHA-256 bajo la cuenta y conversación, sin guardar el texto ni las capacidades de lectura dentro del registro de intención. Tras una respuesta incierta se vuelve a leer y el usuario puede repetir el mismo mensaje de forma explícita. La memoria web dura hasta recargar el documento.

La lectura de mensajes se marca explícitamente con el token de la página que ya se mostró, solo en el cuerpo del POST. La campana de Inicio muestra el contador de notificaciones. La bandeja pagina avisos, marca lectura por `source_type` e ID y navega solo a solicitudes o reservas que la API vuelve a autorizar. No se inicia ninguna operación comercial desde los avisos.

Linux: `npm ci` instaló 807 paquetes. Node 22.13.0 y 24.22.1 pasaron 64/64 cada uno. TypeScript, Expo lint y `git diff --check` salieron 0. Cuatro fixtures se validaron contra OpenAPI. La exportación web produjo 16 rutas y Chromium pasó 18 grupos sin errores de página. Se probó el cursor codificado, marcado explícito sin efecto previo del GET, mismo UUID tras 503 y navegación al recurso del aviso.

Pendientes: validación del contrato en un Laravel aislado y pruebas de teclado, SecureStore y retorno a primer plano en dispositivo físico.
