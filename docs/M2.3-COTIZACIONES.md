# M2.3 · Cotizaciones del cliente

El incremento se apila sobre M2.2. Utiliza OpenAPI 1.4.0 y B3.0 del backend en `a21802f0917132919b0be34087fee03236de2dc0`. [Contrato comercial B3.0](https://github.com/Fernando261/tekora-project/blob/a21802f0917132919b0be34087fee03236de2dc0/docs/api/B3.0-COMMERCIAL.md).

El detalle de solicitud muestra el importe acordado de `journey`, la cotización vigente y el historial paginado. Lee el detalle de cada cotización como snapshot del servidor. Los valores se formatean en MXN a partir de centavos enteros. La comisión se muestra como parte del desglose y el total proviene intacto del backend. Cotizaciones vencidas o históricas conservan su estado e importe.

La emisión se ofrece cuando el recorrido la indica y `commercial.can_issue` está vigente. El cliente envía solo `idempotency_key`. Expo Crypto genera el UUID y SecureStore lo conserva bajo la cuenta y solicitud hasta confirmar la respuesta. En web, el UUID se conserva solo en la memoria del documento. Un resultado incierto refresca el historial y permite repetir voluntariamente con la misma clave. El cliente no cambia el UUID para sortear un conflicto.

La aceptación comprueba la cotización vigente, muestra su precio y requiere confirmar expresamente. Envía solo `{acknowledge:true}`. Los conflictos y resultados inciertos actualizan las lecturas sin forzar un estado local. El importe acordado se toma exclusivamente de la respuesta del servidor. Esta operación no propone un horario, confirma una reserva ni inicia un pago.

La única nueva dependencia es `expo-crypto ~58.0.8`, seleccionada por Expo SDK 58. Las tres moderadas preexistentes permanecen. Pendientes: API Laravel real, almacenamiento de intención SecureStore en Android/iOS y validación Windows. En web un reinicio del documento elimina las claves en memoria. Antes de repetir tras una recarga, se debe consultar el historial.
