# M2.2 · Solicitudes propias y seguimiento

Base móvil `666aa3ba9b018f38779ab8d2c47f6cebf9e79e52`. Rama apilada sobre 10A para revisar únicamente M2.2. Contrato Laravel OpenAPI 1.4.0 en `a21802f0917132919b0be34087fee03236de2dc0`. [OpenAPI vigente](https://github.com/Fernando261/tekora-project/blob/a21802f0917132919b0be34087fee03236de2dc0/docs/api/openapi.json) · [Journey UX-C1](https://github.com/Fernando261/tekora-project/blob/a21802f0917132919b0be34087fee03236de2dc0/docs/api/UX-C1-MOBILE-JOURNEY.md).

- **Servicios → Historial** consulta las solicitudes propias mediante `GET /inquiries`. Incluye paginación, actualización, estados y reintento manual.
- **Detalle del servicio** permite enviar `POST /services/{service}/inquiries` con `{message}` y Bearer. El servidor puede devolver 201 para una solicitud nueva o 200 para una solicitud activa recuperada. El formulario valida el mínimo de 10 caracteres, bloquea envíos simultáneos y, si el resultado es incierto, dirige al historial para reconciliar sin reenviar automáticamente.
- **Seguimiento** combina `GET /inquiries/{id}` y `GET /inquiries/{id}/journey`. Presenta las cinco etapas, el siguiente paso y el historial observado por el backend. Las acciones de otros incrementos aparecen como información. Los enlaces privados pasan por el guard de 10A. Una respuesta exitosa con un Bearer que dejó de ser vigente se descarta.
- Las pantallas de publicación abierta, pagos, reservas y conversación mantienen sus límites. En esta rama las únicas escrituras nuevas son las solicitudes de un servicio publicado. No se replica el workflow de Laravel.
